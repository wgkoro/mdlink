# mdlink v1.0.0 release notes

mdlink v1.0.0 is the initial public release, consolidating existing capabilities. It maintains the established CLI behavior and JSON schema version 1, without introducing new compatibility guarantees.

## Inspect Markdown links

mdlink is a read-only CLI that reads selected files on each run, without a persistent index, database, or daemon. It requires no Git executable or network connection.

| Command | Result |
| --- | --- |
| `outgoing [OPTIONS] TARGET` | Files linked from one Markdown source, with occurrence counts |
| `backlinks [OPTIONS] TARGET` | Markdown sources linking to a file or attachment, with occurrence counts |
| `unresolved [OPTIONS]` | Unresolved links grouped by exact original target text, with every occurrence |
| `version` | Version, full source commit hash, build date, and Go version |

Place options before `TARGET`. Set `--root` to the Markdown directory. Otherwise, mdlink uses `MDLINK_ROOT` or searches upward from the current directory for a directory containing `.obsidian/`. See the [CLI reference](../usage.md) for options and examples.

Supported syntax includes Wikilinks and embeds, Markdown links and images with single-line quoted titles, and full, collapsed, or shortcut reference links and images. Reference definitions must be on a single line within the same source. Links with aliases or fragments, embeds, and self-links all count as occurrences. External URLs and links within supported code or comment regions are ignored. See [syntax and resolution rules](../limitations.md).

For `unresolved`, `--source PATH` and `--sources0-from FILE` limit inspection to selected sources while preserving resolution candidates across the root after exclusions. An empty list selects zero sources. Traversal diagnostics outside the selection are still reported. See [source selection](../usage.md#select-sources-for-unresolved-checks).

`--check-fragments` validates supported Wikilink headings and explicit block IDs for `outgoing` and `unresolved`. Fragment failures produce diagnostics but do not change file counts or add entries to `unresolved.results`. Markdown anchors cannot be validated. See [fragment validation](../limitations.md#fragment-validation).

## Select files and read safely

By default, mdlink applies `.gitignore` files at the root and in visited subdirectories. A `.mdlinkignore` file at the root adds independent exclusions. Excluded directories are not traversed, and excluded files are neither inspected nor used for resolution. Links to excluded files become unresolved; selecting an excluded source or target is an input error.

- `--no-gitignore` disables only `.gitignore`. Root `.mdlinkignore`, `--exclude` paths, and default `.git/`, `.obsidian/`, and `.trash/` exclusions remain active.
- Negation (`!`) can re-include files only within its own rule set. It cannot override other exclusions or re-include a file whose parent directory remains excluded.
- Git's index, configuration, and global rules are not used. mdlink supports a subset of Git's ignore syntax.
- Only regular rule files are read. Invalid or unsupported syntax, unsafe or unreadable files, excessive size, or changes detected during reading result in exit code 1 with empty stdout. Nested `.mdlinkignore` files do not supply rules. Excluding a rule file from the catalog does not disable its rules.

See the [.gitignore](../limitations.md#gitignore-scope) and [.mdlinkignore](../limitations.md#mdlinkignore-scope) rules for details.

Symlinks are skipped with diagnostics unless explicitly allowed by `--follow-symlink` or `MDLINK_FOLLOW_SYMLINKS`. This permission does not extend to nested symlinks. Reads check root boundaries and regular-file identity; duplicate physical files are rejected. Each Markdown body is limited to 64 MiB, with size and modification time checked before and after reading. These checks do not guarantee an atomic snapshot. See [filesystem safety](../limitations.md#filesystem-safety).

## Output and interpretation

Choose text output (optionally with occurrence counts) or JSON. Results and diagnostics have deterministic ordering. JSON uses logical paths, includes all diagnostics, and retains `schema_version: 1`. Source selection and fragment checks add optional fields. See the [JSON contract](../json-schema-v1.md).

`--strict` returns exit code 3 when diagnostics are present while retaining results; otherwise, diagnostics alone result in exit code 0. Runtime errors return exit code 1, and input errors return exit code 2. Fatal errors take precedence over strict mode.

`unresolved` groups exact original target strings, not distinct missing files. Zero results do not prove complete inspection or the absence of problems: consider exclusions, unsupported syntax, source selection, and diagnostics.

Resolution is case-sensitive; ambiguous matches produce diagnostics. mdlink does not implement all CommonMark syntax or validate Markdown anchors. See [scope and limitations](../limitations.md) for supported behavior.

## Performance and resource use

`backlinks` uses a fixed pool of four workers to read and parse sources concurrently, with stable output ordering. The scanner skips processing where relevant syntax cannot occur, preserving validation and diagnostics. Concurrent reads, parser data, and open files increase resource use; the 64 MiB body limit is not a process memory limit. `unresolved` processes sources sequentially and retains occurrences and diagnostics in memory. See [resource use](../limitations.md#resource-use).

[Historical performance reports](../performance/README.md) document the measured versions, workloads, methods, results, and tradeoffs. They are not v1.0.0 measurements and do not guarantee performance on other machines or inputs.

## Distribution and rights

Release builds produce `mdlink-v1.0.0-<goos>-<goarch>` binaries for darwin/arm64, darwin/amd64, linux/amd64, and linux/arm64. They use Go 1.27.1, `CGO_ENABLED=0`, and `-trimpath -buildvcs=false`, and embed the version, full source commit hash, and commit timestamp in UTC. Development builds report `dev` with an unknown commit and build date.

The archive contains four binaries, `SHA256SUMS`, and seven documents: `LICENSE`, `README.md`, `THIRD_PARTY_NOTICES.md`, `docs/usage.md`, `docs/limitations.md`, `docs/json-schema-v1.md`, and these release notes. A separate archive checksum and verification reports accompany the release. For guides and performance reports available only in the repository, use the source commit reported by `mdlink version`. See the [README](../../README.md#documentation).

The [release procedure](../releasing.md) requires byte-identical rebuilds for all four targets, deterministic archives, checksum verification, acceptance tests on actual hosts, CI checks for the release commit, and verification of freshly downloaded assets. Cross-compilation alone does not verify execution on a target platform. Follow the [installation instructions](../../README.md#installation) for your platform.
